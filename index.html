Brainhack discussion proposal

From research files
to lab memory

How can a lab preserve not only data, but enough context to understand, reproduce, restart, and hand over a project years later?
Mixed access

Public, lab-internal, restricted, and sensitive data coexist.

Mixed lifecycle

Projects can be active, published, dormant-but-restartable, or archived.

Lost context

Files survive; rationale, failed approaches, ownership, and analysis history often do not.

Fragmented tools

GitHub, NAS, notebooks, publications and chat each contain only part of the story.

Design target: one durable knowledge layer that can drive storage discovery, provenance, a living website, and permission-aware AI queries.

Proposed architecture

Separate the bytes, the history, and the interfaces

Physical data
NAS · snapshots · backup NAS · S3/R2/object storage
↓
Data management
DataLad / git-annex or DVC; checksums, versions, locations
Publication
Dataverse / OSF for curated public or controlled releases
Bytes can move.
Stable project/dataset IDs should not.

Durable knowledge layer

Project registry
status · access · people · stable IDs
Provenance
dataset → pipeline → commit → analysis → artifact
Lab memory
decisions · protocols · failed approaches · handover
Logical locations
acl://VROT-2025/raw → current physical backend
Open formats: YAML + Markdown + checksums + Git history
Automated website
Quarto/static site rebuilt from the same registry
Search / index
Metadata + full-text + optional semantic retrieval
AI agent
Discord / LINE / Web: identity → ACL filter → retrieval → answer + provenance
Security boundary:
authorization filtering happens before semantic retrieval. AI does not browse the NAS directly.
Components are replaceable; the metadata/provenance contract is durable.2 / 3
